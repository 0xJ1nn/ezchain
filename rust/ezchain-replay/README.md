# ezchain-replay

Read-only **balance replay projection** from an ordered tape of ledger entries.

Oracle: `packages/core-py/src/ezchain_core/ledger.py` (`replay_balances`,
`assert_balanced`, `replay_position`, `realized_pnl`, and the account-naming
helpers). Ported under ADR-0049/0050/0052 with recorded behavioural parity.

## What is ported

- `replay_balances`: per-account exact token amount and exact USD minor units,
  canonical and account-sorted.
- `assert_balanced`: tolerance-free conservation of a journal group (zero
  minor units), with the exact `LedgerError` message on failure.
- `replay_position`: `(quantity, cost_basis_usd)`, including the zero-quantity
  cost reset and the negative-quantity refusal.
- `realized_pnl`: the realized-contra replay, including Python's ambient
  unary-minus rounding at 28 significant digits.
- Account naming: `cash:USD`, `fees:USD`, `pnl:realized:USD`,
  `position:{chain}:{token}`, and the funding contra constant/prefix.
- Typed refusals: `SubQuantumError`, `MoneyError`, `InvalidOperation`,
  `LedgerError` (with exact total), `ValueError`.

Arithmetic uses `ezchain-decimal` throughout; no Decimal logic is duplicated
here and there are no new dependencies.

## This is a projection, not an accountant

Per CONTRACT I1 the Python ledger remains the sole accountant. This crate does
no I/O, opens no database/file/socket/clock, holds no keys, and writes no
entries, balances or position rows. Callers pass a tape they already own; the
crate folds it into derived values or refuses a tape that breaks conservation.

## Gate

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
.venv/bin/python rust/ezchain-replay/tests/parity_oracle.py --check
```

`tests/parity_fixture.txt` is generated by `tests/parity_oracle.py`, which runs
the real `ledger.py` under the project venv. A held-out corpus is checked with
`EZ_REPLAY_SEED=<n>` (generate to `EZ_REPLAY_FIXTURE=<path>`) and
`EZ_REPLAY_FIXTURE=<path> cargo test -p ezchain-replay --test parity`.
A parity failure is an implementation bug; regenerate the fixture from the
oracle only when the recorded Python behaviour itself changes.
