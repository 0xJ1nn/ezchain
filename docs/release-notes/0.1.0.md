# Release 0.1.0 — in preparation

Status: in preparation · Current build: PAPER · Live execution targeted behind the readiness gate

0.1.0 is the first public release of ezCHAIN and the only launch lane. It carries the
complete product: the paper surface and the remaining screens and onboarding, data ingest,
authentication and roles, execution groundwork, and live trading with real money. The
version identifier stays `0.1.0`. Live mode is targeted, not enabled: this build ships with
no keys, signing, custody or live venue, and mode `live` refuses with `GATE_NOT_MET` until
the readiness rules in [LIVE-EXECUTION.md](../LIVE-EXECUTION.md) are satisfied and the
maintainer enables it. No dates are promised. The product ships with no strategies.

## What is in this release

### Market data and observation

Live market reads across a 25-chain registry, with source and age carried on every row,
per-chain quote ladders, and DexScreener market data with Jupiter quote clients. The
stream contract is versioned (#548). The firehose entry gate refuses stale observations
and reports measured feed health instead of a fresh-looking zero. Firehose discovery is
not a live trading path.

### Paper ledger and PnL

An append-only paper ledger records cash, positions and realized PnL; a fill writes its
journal entries in the same transaction as the position update, and reconciliation
reports an independent cash-versus-fills check. The intent-to-journal pipeline (#269)
and transaction-to-intent binding (#274) are merged groundwork for a shared execution
path; paper orders still take the current paper path.

### Strategies, automations and backtests

Declarative and visual graph strategies, external Python strategy plugins in a
supervised worker, a strategy graph template (#549) and a backtester. The product ships
with no strategies; any strategy is supplied by the operator and runs in paper mode.

### Operator surface

Health, readiness, metrics, a persisted kill switch, reconciliation, limits, alerts,
attribution and performance reads, with the gateway supervisor merged (#550). The web
tree has 36 shipped routes — 18 wired, 13 partial and 5 fixture-only — and the client's
85 HTTP endpoints are implemented.

### HTTP API

The API derives execution mode on the server and records the gate (#265). Reads are open
and mutations require a bearer token. No endpoint places a live order in this build; the
gated live path is part of the release work.

### MCP and agent packs

An MCP server, Hermes and OpenClaw packs, and scoped agent keys. Paper-only mutation
tools are hidden by default and remain bearer-authenticated. There is no live order tool in
this build; live tooling is gated by the same readiness rules.

### Rust core migration

Merged migration waves through native-host routing (#380, #393, #397, #405, #408,
#411, #415, #417, #419–#422, #426, #429, #432, #435, #436). The language-map change is
not included in this release.

### Desktop and self-hosting

Desktop first-run setup (#552), a Linux desktop build using embedded SQLite, and a
Docker Compose paper stack. The dependency licence gate is merged (#551); the
per-manifest licence-identifier work (#523) is still open.

### Live execution (targeted, gated)

This release targets live trading with real money: the executor, vault and custody path,
key lifecycle runbooks, live venues and reconciliation are in scope. Live mode stays
disabled in this build. It is enabled only after the readiness rollup in
[LIVE-EXECUTION.md](../LIVE-EXECUTION.md) is recorded and the maintainer turns it on; this
note does not claim that live trading works today.

## Known limitations

- **No multi-user ledger isolation.** One instance is one paper workspace. Scoped agent
  keys ship, but there is no per-user authentication or ledger partitioning; the
  deployment admin token is a shared operator secret.
- **Docker re-drill outstanding.** The recorded Compose drill was at an earlier migration
  head. The stack has not been re-drilled at the current head.
- **Hosted surface untested.** No hosted multi-user deployment has been exercised;
  self-hosting is the supported path.
- **Live execution is not enabled in this build.** The release targets live trading, but
  there are no keys, signing, custody, vault or live venues yet and mode `live` refuses with
  `GATE_NOT_MET`. The readiness rollup, custody and key runbooks and a venue rehearsal must
  be recorded, and the maintainer must enable live mode, before a real order can be placed.
  Non-Solana fills remain paper marks until then.
- **The web surface is incomplete.** Thirteen routes are partial and five are fixture-only;
  sign-in, onboarding and the wireframe gallery have no route.
- **Market coverage is 22 of 25 chains.** The other three report no data, never zero.

## Upgrade notes

This is the first public release, so there is no previous tagged version to upgrade from.
A fresh install starts in PAPER mode; follow the setup in the repository README and do not
point this build at funds. The plugin SDK, agent packs and HTTP surface may change between
minor releases. Tagging and publishing are maintainer actions.
